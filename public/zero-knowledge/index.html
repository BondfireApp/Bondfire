ZERO-KNOWLEDGE // PLAIN LANGUAGE

The server should not need to read your private work.

Bondfire encrypts private organization content on the client before persistence. The server stores ciphertext, while authorized members decrypt the information they have permission to use.

THE BASIC FLOW

Three steps, without the cryptography sermon.

01 // CREATE

You create private content

Members work inside a private Organization Workspace.

02 // ENCRYPT

Your client encrypts it

Private organization content is encrypted before it is persisted.

03 // DECRYPT

Authorized members read it

Members with the required organization, module, and role access decrypt the private content they are allowed to use.

WHAT THIS MEANS

Bondfire's storage layer does not need the plaintext copy.

For private organization content, Bondfire is designed around ciphertext-authoritative storage. That means private content is stored encrypted rather than stored as readable application data that the server must inspect to function.

This reduces how much private organizational information the infrastructure itself needs to possess in readable form.

WHAT THIS DOES NOT MEAN

“Zero-knowledge” is not “the service knows literally nothing.”

Running an online service still involves operational information. Accounts exist. Network requests happen. Authentication and authorization happen. Devices can be compromised. Metadata can matter. No serious security model improves by pretending those facts disappeared.

  • Zero-knowledge protection applies to private organization content, not to information a group intentionally publishes.
  • It does not make a compromised device trustworthy.
  • It does not replace strong account security, careful membership practices, or sensible backups.
  • It does not make unnecessary data collection harmless. The safest sensitive information is often the information a group never collects.

PUBLIC SURFACES

Public means public.

Publishing is an explicit boundary.

Information deliberately published through an Organization Page, Publication Site, public event, or another public-facing surface is intentionally readable. Bondfire keeps those public surfaces conceptually separate from private workspace data.

ACCESS

Encryption and authorization work together.

Private content is not merely “encrypted somewhere.” Bondfire also limits decryption to authenticated members with the appropriate organization, module, and role access. The point is to keep both storage and access boundaries narrow.

VERIFY IT

You do not have to take the homepage's word for it.

Bondfire is free software. The source code is public, including the application code implementing the client-side encryption and private-storage paths. Security claims are more useful when people can inspect the machinery instead of admiring a padlock icon and hoping for the best.
