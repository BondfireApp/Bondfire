ABOUT BONDFIRE

Private infrastructure for people doing things together.

Bondfire is modular coordination infrastructure for mutual-aid networks, community organizations, collectives, gatherings, projects, and other groups that need useful tools without turning themselves into a data product.

WHY BONDFIRE

Coordination without platform surveillance

Your private organization data is encrypted before Bondfire stores it. Private workspace content should not need to become infrastructure-readable plaintext.

Modular instead of monolithic

Organizations enable the tools they actually need instead of inheriting one enormous mandatory stack.

Private operations stay distinct from public publishing

Private workspace data and intentionally public Organization Pages, Publication Sites, and public events have different security expectations.

HOSTED + SELF-HOSTED

Hosted

Use Bondfire’s hosted infrastructure while the project operates the server-side service.

Self-hosted

Deploy the same core software independently. Infrastructure security, logging, backups, and operations become the self-hoster’s responsibility.

PRIVACY BOUNDARY

Public means public.

Information deliberately published through an Organization Page, Publication Site, public event, or another public surface is intentionally readable and separate from private workspace data.

Zero-knowledge is a boundary, not a magic spell.

It does not make compromised devices trustworthy, stop screenshots, neutralize malicious authorized members, or erase operational metadata. See What Bondfire Knows and the Threat Model.

TRACKING

The current application does not ship an advertising tracker, cross-site tracking SDK, or product analytics SDK. That is not the same thing as “zero metadata”: accounts, requests, authorization state, timestamps, and infrastructure-level operational information still exist where required to run the service.
