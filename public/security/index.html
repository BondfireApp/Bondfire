SECURITY

Security is a set of boundaries, not a magic adjective.

Bondfire is designed so private organization content is encrypted on the client before persistence. Server-side authorization and scoped key access work alongside encryption to limit who can retrieve and decrypt private records.

PRIVATE STORAGE

Ciphertext is authoritative for private organization content.

The client uses authenticated encryption for private records before they are sent for persistence. The current implementation uses AES-GCM and binds encrypted records to organization, content type, and record identity. Keys are scoped and retrieved through authenticated, role-gated paths.

Don’t trust the claim. Inspect the implementation. See privateCrypto.js and the repository’s private-storage regression tests.

ACCESS CONTROL

Authentication, authorization, and encryption are separate controls.

Authentication

Hosted Bondfire uses account sessions and cookies to identify signed-in users.

Authorization

Organization, module, and role boundaries determine which server resources a member may access.

Key access

A member still needs the appropriate scoped encryption key on an authorized device to decrypt private content.

KEYS, RECOVERY, AND EMERGENCY ACTIONS

Bondfire supports device-bound key provisioning, scoped role keys, recovery paths, key rotation, and an emergency protocol for lockdown and destructive actions. Recovery material is sensitive. Losing or exposing it can respectively make data unavailable or make encrypted data easier to unlock.

Destructive actions are intentionally distinct from ordinary organization management. Emergency controls are not a substitute for backups or operational planning.

LIMITATIONS

Encryption does not solve compromised endpoints or bad decisions.

  • Compromised member devices or endpoint malware.
  • Malicious or careless authorized members.
  • Screenshots, copied plaintext, or exported data.
  • Stolen unlocked devices and weak account security.
  • Coercion of members.
  • Exposed recovery material.
  • Operational metadata created by running an online service.
  • Unnecessary collection of sensitive information.
The safest sensitive information is often the information a group never collects.

HOSTED VS SELF-HOSTED

Hosted

Bondfire operates the server-side infrastructure. The hosted service can make claims about that infrastructure and its code deployment, subject to the limitations documented here.

Self-hosted

The same core software can be deployed independently. The self-hoster becomes responsible for infrastructure configuration, logging, updates, backups, domains, and server security.

RESPONSIBLE DISCLOSURE

Do not post exploitable details, credentials, private user information, or active vulnerability reproduction data in public issues. The repository currently does not publish a dedicated security email, so this page does not invent one. Check the repository security surface for the current private reporting mechanism before sharing sensitive details.
