WHAT BONDFIRE KNOWS

Zero-knowledge private data does not mean zero metadata.

This page separates private organization content from the information a hosted service necessarily processes to operate.

PRIVATE ORGANIZATION CONTENT

Bondfire should receive ciphertext, not readable private records.

Private organization records are intended to be encrypted in the client before persistence and decrypted by authorized clients. Hosted infrastructure stores the encrypted representation and does not need plaintext private organization content to provide storage.

ACCOUNT + AUTHENTICATION INFORMATION

The hosted service necessarily processes account identifiers and authentication/session information in order to sign people in, maintain sessions, determine organization membership, enforce permissions, and provision encryption keys to authorized accounts/devices. Zero-knowledge private storage does not hide the existence of an account or membership relationship from the authorization system.

OPERATIONAL METADATA

Running Bondfire necessarily creates some operational information around requests and records: resource identifiers, timestamps used by application records, request routing information, and infrastructure-level logs or diagnostics produced by the hosting stack. The codebase does not claim that private-content encryption removes network or infrastructure metadata.

Bondfire does not describe this as “zero metadata,” because that would be nonsense wearing a privacy badge.

PUBLIC CONTENT

Public means public.

Organization Pages, Publication Sites, public events, and other explicitly published surfaces are intentionally readable. They exist outside the private workspace boundary because publishing is the user’s explicit choice.

ANALYTICS + TRACKING

The current application dependency set does not include an advertising tracker, cross-site tracking SDK, or product analytics SDK. Bondfire does not use private organization content to build advertising profiles.

This is distinct from ordinary operational logging by the application or hosting infrastructure. If telemetry is introduced later, this page should be updated before the change is presented as compatible with the existing claim.

THE USEFUL SUMMARY

Can know

That accounts, organizations, memberships, requests, public content, and encrypted private records exist, plus operational metadata required to run the hosted service.

Should not know

The plaintext contents of private organization records merely because the hosted server stores them.
